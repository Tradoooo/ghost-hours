# Relaunching the demonstration

The demo is not a memory: every number it shows is recomputed by the pipeline, every
proof it ships is a real one that was anonymised, and the whole thing is relaunched with one
command. This file is the procedure, for this machine or for a fresh one.

## One command

```bash
git clone https://github.com/Tradoooo/ghost-hours.git && cd ghost-hours
pnpm install
pnpm demo
```

`pnpm demo` runs, in order, and stops at the first failure:

| Step | What it does | Where the guarantee lives |
|---|---|---|
| **fixture** | recomputes `fixtures/real-month/expected.json` from the evidence, through the real mapping + sessionizer | `fixtures/real-month/regenerate.mjs` |
| **anchor** | hashes the day's proofs into a chained ledger and verifies it | `scripts/anchor-evidence.mjs` |
| **check** | unit tests + typecheck + lint | `pnpm test` |
| **build** | the static site in `apps/web/dist` | `pnpm build` |
| **browser** | the built site in a real browser: it boots, the month's figures reach the screen, nothing leaves the page | `pnpm e2e`, served by the suite itself |

The test count is not written here on purpose: it changes with the specs, and a number copied into
a doc is a number that goes stale. `pnpm test` prints the truth.

The **browser** step needs a system browser (`google-chrome`, `chromium`, or
`GHOST_HOURS_BROWSER`). Without one it reports `skipped` and `pnpm demo` exits **3**: a check that
did not run is not a check that passed. It used to stop at the build, which is how a desktop CSS
bug shipped green — see `docs/BROWSERS.md`.

The demo month ships **already collected, anonymised and anchored**, so a fresh machine never needs
the author's repositories, a real clock or a network connection.

## The numbers can never drift

`fixtures/real-month/expected.json` is regenerated by the pipeline, and `real-month.test.ts`
recomputes it again on every `pnpm test`. If the product's algorithm changes, the test fails — so a
demo built by this procedure shows the numbers the code produces, never the numbers someone remembers.

## Swapping in a different month

The fixture is October 2026, anonymised. To show *your* month instead:

```bash
# 1. collect, read-only, never reading a commit message
pnpm collect ~/code --author you@example.com --since 2026-10-01 --until 2026-10-31 \
  --no-summaries --out /tmp/mine.json

# 2. anonymise every identifying string
node scripts/anonymize-evidence.mjs /tmp/mine.json fixtures/real-month/evidence.json --print-map

# 3. recompute the numbers and the site
node fixtures/real-month/regenerate.mjs
pnpm demo --from check
```

The mapping printed by `--print-map` stays out of the repository: it is the only link between a
pseudonym and a real project.

## Freezing a real month (the anti-backdating guarantee)

For a month you actually invoice, the anchor is the daily habit that makes inventing yesterday
detectable:

```bash
node scripts/anchor-evidence.mjs add evidence.json anchors.jsonl   # each evening
node scripts/anchor-evidence.mjs verify evidence.json anchors.jsonl  # on invoice day, for the client
```

Publish `anchors.jsonl` somewhere the client cannot edit (their server, a public repository, a
timestamping service). From then on, moving a commit from the 25th to the 3rd breaks the chain —
`verify` says exactly where. That is the demonstration in `scripts/anchor-evidence.test.mjs`, run
with the rest.

## The video

The silent cut of the real month is recorded on a machine with a display:

```bash
node ~/Bureau/ghost-hours-video/record-real.mjs https://tradoooo.github.io/ghost-hours/
```

The voice-over and the final edit under three minutes remain a human's job: the script documents,
it does not narrate.
